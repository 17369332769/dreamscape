## 一、目标与边界

### MVP 目标

用最小可行版本验证两件事：

1. 玩家是否愿意持续体验 AI 互动剧情
2. 玩家是否愿意为后续章节消耗梦境石

### MVP 范围

- 单世界观：古风仙侠
- 单平台优先：微信小程序
- 单互动方式：选项式互动
- 1 套角色创建流程
- 3 个章节
- 基础属性检定
- 基础背包与道具使用
- 章节结算与下一章入口
- 模拟梦境石消耗
- 内容审核兜底

### 非目标

- 不做自由输入
- 不做多世界观
- 不做社区
- 不做真实支付
- 不做复杂商店
- 不做实时图片生成

## 二、里程碑拆分

### M0：方案确认

目标：把影响研发的关键不确定项定下来

任务：

- 确认 AI 模型与供应商
- 确认内容审核 API 供应商
- 确认微信小程序主体与认证状态
- 确认 Supabase 项目环境
- 确认第一章叙事文风与输出长度
- 确认后台是否使用现成 admin 框架

交付物：

- 技术选型结论
- 环境账号清单
- 第一章风格样例

验收标准：

- 所有外部依赖都有明确负责人与可用账号
- AI 输出格式、文风、成本范围达成一致

### M1：基础工程初始化

目标：搭起前后端最小可运行工程

任务：

- 初始化 Taro + React + TypeScript 小程序工程
- 初始化 Next.js API 服务
- 配置 ESLint、TypeScript、环境变量管理
- 配置开发环境与测试环境
- 设计前后端目录结构与命名规范
- 建立基础请求封装、错误处理、日志方案

交付物：

- 前端工程骨架
- 后端工程骨架
- `.env.example`
- 工程约定说明

验收标准：

- 小程序端可以本地启动
- API 服务可以本地启动
- 前后端可通过测试接口完成一次联通

### M2：数据库与基础数据层

目标：完成 MVP 所需表结构与访问层

任务：

- 建立 `users` 表
- 建立 `characters` 表
- 建立 `saves` 表
- 建立 `messages` 表
- 建立 `item_definitions` 表
- 建立 `inventories` 表
- 建立 `transactions` 表
- 建立 NPC 相关表的 MVP 子集
- 建立成就/图鉴表时仅保留未来兼容字段，若当前不用可延后
- 增加关键索引
- 增加幂等字段
- 编写数据库迁移脚本
- 封装基础 repository/service 层

交付物：

- 数据库 schema
- 迁移脚本
- 种子数据脚本

验收标准：

- 本地或测试环境可一键建表
- 能插入并查询用户、角色、存档、消息、背包、交易数据
- 重复请求不会造成关键数据重复写入

### M3：认证与角色创建

目标：完成用户进入游戏前的必要流程

任务：

- 实现 `POST /api/auth/login`
- 实现微信登录态换取本地用户
- 生成 JWT 或等效会话令牌
- 实现 `POST /api/characters`
- 实现角色属性点校验
- 实现特质选择规则校验
- 保存角色与初始状态
- 设计角色创建页 UI
- 设计角色预览页 UI

交付物：

- 登录接口
- 角色创建接口
- 小程序登录与建角页面

验收标准：

- 新用户可完成登录
- 用户可合法分配属性并创建角色
- 非法入参会被正确拦截

### M4：章节启动与存档体系

目标：让角色进入第一章并持有可推进的存档

任务：

- 实现 `POST /api/story/start`
- 初始化章节、回合数、阶段、初始剧情上下文
- 注入第一章骨架数据
- 生成首段 narrative 与初始 3 个选项
- 建立章节状态机字段
- 设计首页进入剧情与继续存档逻辑

交付物：

- 开始章节接口
- 初始章节数据
- 存档读写逻辑

验收标准：

- 角色能进入第一章
- 能拿到首屏剧情和选项
- 同一角色可以正确恢复当前进度

### M5：剧情引擎与 AI 结构化输出

目标：实现选项推进的核心闭环

任务：

- 实现 `POST /api/story/choice`
- 校验 `save_id`、`round`、`option_id`
- 校验存档状态是否可推进
- 校验选项前置条件
- 根据章节回合与关键节点推进阶段
- 组装 Prompt：世界规则、角色信息、短期记忆、长期摘要、当前行动
- 调用 AI 接口生成剧情 JSON
- 按 Schema 校验 AI 输出
- 解析 narrative、options、scene_tag、mood、check 等字段
- 落库 messages / saves / NPC 关系变化
- 增加失败重试与兜底文案

交付物：

- 剧情推进接口
- Prompt 组装模块
- AI 响应解析模块
- JSON Schema 校验模块

验收标准：

- 玩家每次选择都能返回下一回合剧情
- AI 输出异常时系统能兜底而不是中断
- 回合推进、阶段流转与消息落库一致

### M6：属性检定与状态系统

目标：把“选项推进”升级为“规则驱动推进”

任务：

- 实现属性检定计算逻辑
- 支持 `str / int / cha / lck / wil` 五项属性
- 支持道具加成与状态惩罚
- 实现 `normal / injured / confused / locked / chapter_end` 状态管理
- 将检定结果回写到剧情响应和日志
- 增加关键选择、隐藏选项触发规则

交付物：

- 检定服务
- 状态机服务
- 关键节点配置

验收标准：

- 不同属性值能显著影响检定结果
- 受伤、心乱等状态可正确影响后续回合
- 重复提交会因 `locked` 或幂等机制被拦截

### M7：背包与道具系统

目标：实现章节内外最基础的道具闭环

任务：

- 建立道具定义数据
- 实现剧情奖励发放
- 实现背包读取接口
- 实现 `POST /api/inventory/use`
- 支持属性检定目标类道具使用
- 支持章节关键道具解锁选项
- 在小程序中实现背包入口、列表、详情、使用反馈

交付物：

- 道具定义种子数据
- 背包接口
- 道具使用接口
- 背包 UI

验收标准：

- 玩家能获得、查看、使用道具
- 道具效果能影响检定或剧情选项
- 重复使用、无效使用有清晰拦截和提示

### M8：章节结算与下一章入口

目标：完成单章体验闭环

任务：

- 根据关键选择、检定结果、NPC 好感、持有道具判定结局
- 调用 AI 生成结局叙事
- 发放章节奖励
- 写入章节结算数据
- 将存档更新为 `chapter_end`
- 返回结算页数据
- 设计结算页 UI 与下一章入口提示
- 实现第二章入口梦境石消耗提示

交付物：

- 结局判定模块
- 章节结算接口
- 结算页 UI

验收标准：

- 章节能稳定结束
- 不同路径可导向不同结局
- 玩家可从结算页继续进入下一章入口

### M9：经济账本与模拟消耗

目标：验证付费前置逻辑，不接真实支付

任务：

- 定义梦境石字段与账户逻辑
- 实现扣费优先级
- 实现交易记录落库
- 实现第二章/第三章入口的消耗校验
- 实现“余额不足”提示与兜底流程
- 增加成本统计字段，记录 AI 调用成本估算

交付物：

- 账本服务
- 交易记录接口或内部服务
- 章节消耗逻辑

验收标准：

- 章节入口能正确扣减或拦截
- 所有变动可在账本中追溯
- 不会因重复提交导致重复扣费

### M10：内容审核与安全兜底

目标：保证内容可用且风险可控

任务：

- 接入输入审核
- 接入输出审核
- 增加本地敏感词和规则兜底
- 审核失败时返回替代文案
- 记录审核日志
- 增加举报入口和基础风控记录

交付物：

- 审核服务
- 敏感词规则
- 审核失败兜底策略

验收标准：

- 输入与输出都经过审核链路
- 审核失败不会打断主流程
- 风险内容可回溯

### M11：埋点、后台与运营基础

目标：具备 MVP 内测所需的数据观察能力

任务：

- 实现核心埋点事件
- 建立关键漏斗统计口径
- 提供基础管理后台
- 后台支持用户、角色、存档、消息、交易查看
- 后台支持剧情问题排查和审核记录查看

交付物：

- 埋点事件清单实现
- MVP 后台页面

验收标准：

- 能统计序章完成率、第一章完成率、第二章入口点击率
- 运营或研发能从后台排查用户问题

### M12：测试、联调与内测

目标：在小范围真实用户里验证闭环

任务：

- 完成功能测试
- 完成 AI 稳定性测试
- 完成审核链路测试
- 完成兼容与性能测试
- 组织 10-30 人内测
- 收集剧情质量、留存、完成率、异常率数据
- 输出下一版结论

交付物：

- 测试用例
- 测试报告
- 内测复盘文档

验收标准：

- 新用户完成序章率达到目标
- 第一章完成率达到目标
- 第二章入口点击率达到目标
- AI 输出审核拦截后可恢复率达到目标

## 三、推荐研发顺序

建议按下面顺序推进，避免先做非关键能力：

1. M0 方案确认
2. M1 基础工程初始化
3. M2 数据库与基础数据层
4. M3 认证与角色创建
5. M4 章节启动与存档体系
6. M5 剧情引擎与 AI 输出
7. M6 属性检定与状态系统
8. M7 背包与道具系统
9. M8 章节结算与下一章入口
10. M9 经济账本与模拟消耗
11. M10 内容审核与安全兜底
12. M11 埋点、后台与运营基础
13. M12 测试、联调与内测

## 四、建议的首批 Sprint

### Sprint 1

目标：跑通“登录 -> 创建角色 -> 开始第一章”

任务：

- 完成 M0
- 完成 M1
- 完成 M2 的最小建表
- 完成 M3
- 完成 M4

验收：

- 用户能登录并创建角色
- 用户能进入第一章首屏

### Sprint 2

目标：跑通“选择一个选项 -> 生成下一段剧情”

任务：

- 完成 M5
- 完成 M6 的基础检定能力
- 补充第一章骨架

验收：

- 玩家能连续推进至少 5 回合
- AI 输出异常时有兜底

### Sprint 3

目标：跑通“拿道具 -> 用道具 -> 影响剧情”

任务：

- 完成 M7
- 强化 M6 状态影响

验收：

- 背包可用
- 道具可影响选项或检定

### Sprint 4

目标：跑通“完成第一章 -> 进入第二章提示消耗”

任务：

- 完成 M8
- 完成 M9
- 完成 M10 基础审核

验收：

- 第一章可完整通关
- 第二章入口有梦境石消耗逻辑

## 六、关键风险

### AI 输出不稳定

风险：

- JSON 不合法
- 叙事风格漂移
- 选项质量不稳定

应对：

- 强约束 Schema
- 失败重试
- 兜底文案
- 固定第一章骨架

### 审核误伤或漏审

风险：

- 正常内容被拦截
- 风险内容未拦截

应对：

- 第三方审核 + 本地规则双层兜底
- 审核失败降级回复
- 留审计日志

### 成本过高

风险：

- 单章 AI 成本高于可接受范围

应对：

- 控制上下文长度
- 做长期记忆压缩
- 固定回合字数
- 优先验证付费意愿

### 工期蔓延

风险：

- 功能边界失控

应对：

- 严格按 MVP 范围推进
- 禁止提前做自由输入、多世界观、真实支付

## 七、建议你现在立刻确认的事项

1. AI 供应商和具体模型
2. 审核 API 供应商
3. 数据库环境是否直接用 Supabase
4. 当前是否先只做微信小程序
5. 第一章剧情骨架是否已经定稿
6. 后台是临时自建还是接现成 admin

---

## 八、下一步建议

如果要尽快进入实际开发，建议下一步直接做下面两件事：

1. 初始化前后端工程骨架
2. 先落数据库 schema 与第一批 API

这样可以最快跑通第一条主链路：

`登录 -> 创建角色 -> 开始第一章 -> 提交选项 -> 返回下一段剧情`
